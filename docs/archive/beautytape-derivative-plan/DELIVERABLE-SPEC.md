# 작업 2 — 산출 문서 세부 형식

각 문서의 필수 섹션. 항목이 비면 "미정 + 사유"로 명시하고 넘어간다 (빈 채 생략 금지).

## A-BRIEF.md

1. 컨셉 한 줄 (원본과의 차이 + 왜 디자인 중심인지가 한 문장에 들어가야 함)
2. 타깃 사용자 2~3 페르소나 (미용실 방문 전 시안 준비, 이미지 변신 탐색 등)
3. 차별점 3개 이하 — 각각 "원본에서는 불가능했던 경험" 형태로 서술
4. 포함 범위 / 제외 범위 표 (제외 항목엔 사유)
5. 성공 기준 — "첫 화면 3초 안에 무엇이 보여야 하는가" 포함

## B-SCREENS.md

화면마다 아래 4요소:

1. 화면 이름 + 흐름 내 위치 (홈 → 탐색 → 적용 → 비교/기록)
2. 텍스트 와이어 (ASCII 박스 허용, 영역별 우선순위 번호)
3. 디자인 의도 2~3문장 — 이 화면이 주는 감정/인상
4. 상태 정의: 비어 있음(empty) / 로딩 / 오류 / 완료 각각의 모습

최소 화면 세트: 홈(에디토리얼 히어로), 스타일 갤러리(무드보드), 염색 팔레트(색상환/톤),
내 사진 적용, 나란히 비교, 저장 기록. 6개 초과 시 과잉 여부 자기검증.

## C-TOKENS.md

1. 계승 vs 신규 결정문 + 근거 (PLAN.md §2-4의 기준 3개 각각에 답할 것)
2. 토큰 표: `이름 | 값 | 용도 | 원본 대비 (동일/변경/신규/폐기)`
   - 색, 타이포(패밀리/스케일/자간), 간격, 라운드, 그림자, 글래스 전부
3. 한글 타이포 명시: 헤드라인 serif fallback 체인과 본문 sans 체인, 한글 줄바꿈 정책
4. WCAG AA 대비비 사전 계산: 본문/muted/액센트 텍스트가 올라가는 배경 조합 전부

## E-BREAKDOWN.md

1. 마일스톤 3개 이하: M1 디자인(토큰+화면 스펙 확정) → M2 마크업(정적 화면) → M3 로직(추천/적용/저장)
2. 각 작업 항목: `ID | 마일스톤 | 내용 | 선행 작업 | 완료 기준(검증 가능한 문장)`
3. M1이 끝나기 전에 M3 작업을 시작하지 않는다는 순서 제약 명시
4. 첫 커밋 후보 3개 — 가장 작은 착수 단위
