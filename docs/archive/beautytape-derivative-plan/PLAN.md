# 작업 2 — "헤어 디자인 특화" 파생 프로젝트 설계 계획

역할: BeautyTape에서 파생된 신규 프로젝트 "헤어 디자인 특화 버전"의 리드 디자이너 겸 기획자.
목표: 4모듈 종합 앱이 아니라 **헤어 디자인 한 가지에 몰입한 디자인 중심 앱**의 설계 문서를 만든다.
핵심 정신: 기능 나열이 아니라 **디자인·비주얼 경험**을 특색으로 내세운다.

이 단계의 산출물은 **설계 문서만**이다. 신규 저장소 생성, 코드 작성, 에셋 생성은 하지 않는다.

- 원본: `/Users/kwon/vscode/duct-tape-beauty-recommender` (로컬 설치형, MIT, NomaDamas)

  - `src/modules.mjs` (2,491줄) — 헤어 추천/염색 팔레트 로직. 헤어 샘플 매핑은 42–61행:

## 2. 설계 요구 (산출 문서가 답해야 할 질문)

1. **컨셉 한 줄** — 원본과 무엇이 다르고 왜 "디자인 중심"인가
2. **정보 구조** — 홈 → 스타일 탐색 → 내 사진 적용 → 비교/기록 흐름을 헤어 몰입형으로 재편한 화면/탭 구성
3. **헤어 전용 심화 기능** (모두 디자인 강조 관점으로):
   - 스타일 갤러리/무드보드형 탐색 (컷 × 펌 × 염색 × 앞머리 조합)
   - 염색 팔레트의 색상환/톤(웜쿨·명도·채도) 기반 시각화 — `colorTheory.mjs` 재사용 가능성 판단 포함
   - 얼굴형/분위기 → 스타일 매칭의 **시각적 근거** 표현 (점수 숫자가 아니라 보이는 이유)
   - 전/후 및 후보 간 나란히 비교의 에디토리얼 레이아웃
4. **비주얼 디자인 방향** — 무드, 컬러 아이덴티티, 타이포(헤어 살롱/에디토리얼 톤), 카드·스와치·갤러리 스타일.
   **원본 Atelier 토큰 계승 vs 새 아이덴티티 수립을 반드시 결정하고 근거 제시.**
   판단 기준: (a) 원본과의 브랜드 연속성 가치, (b) "헤어 살롱" 무드에 warm blush/cocoa가 그대로 맞는가,
   (c) 토큰 재사용 시 유지보수 이득 vs 차별화 손실
5. **반응형·접근성 기준** — 모바일 우선, WCAG AA

## 4. 절차

1. `VERIFICATION.md`의 최소 실험으로 재사용 후보 자산의 실재와 형태를 확인 (읽기 전용)
2. 원본 헤어 모듈 화면을 1회 육안 확인해 현재 UX의 한계(4모듈 속 탭 하나로서의 제약)를 기록
3. A → B → C → D → E 순서로 문서 작성 (C는 B의 화면 요구에서, D·E는 A~C의 결정에서 도출)
4. 각 문서 말미에 "이 결정이 '디자인 중심' 정신에 어떻게 기여하는가" 1문장 자기검증

## 5. 제약

- 로컬 설치형·프라이버시 우선 유지: 127.0.0.1 바인딩, 사용자 PC 저장. LAN/public 호스팅 전제 금지
- 제외: 실시간 AR/카메라 추적, 결제, 소셜 공유, 3D 아바타, 얼굴 정밀 마스킹, 전문 진단
- 외부 코드/이미지 에셋 복사 금지 — MIT 경계 준수, 콘셉트 참고만. 원본(자체 저장소) 자산 재사용은 `D-MODULES.md`에 출처 명시 조건으로 허용
- 기능 과잉 금지: 새 기능 하나를 제안할 때마다 "이것이 비주얼 경험 완성도를 높이는가"를 통과해야 함
- 이 단계에서 코드·프로토타입 작성 금지. 문서만.
